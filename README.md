# InOutData

Ветка: `2-create_InOutData128_112_8`. Состояние: `ec57ecc`.

## Изменения относительно первого этапа

Сохранён `InOutData320`; добавлены `InOutData128`, `InOutData112` и `InOutData8`. Для каждого нового типа есть заголовок в `include/` и реализация в `src/`.

| Тип | Полезные данные | Представление |
| --- | --- | --- |
| `InOutData128` | 128 бит, 16 байт | 4 слова uint32_t, массив байт, 2 слова uint64_t |
| `InOutData112` | 112 бит, 14 байт | 4 слова uint32_t; в последнем используются младшие 16 бит |
| `InOutData8` | 8 бит, 1 байт | uint8_t packed, байтовый доступ и uint32_t words[1] |

Полезная длина и размер объекта различаются. В частности, объединение `InOutData112` вмещает 16 байт слов, а `InOutData8` содержит 32-битное представление. `NUM_BYTES` задаёт объём полезных байт, а не универсальное значение `sizeof`.

## Основные возможности

128- и 112-битные контейнеры поддерживают доступ к словам, байтам и битам, работу с векторами и массивами, текстовый вывод и преобразования порядка байт. Для 112-битного типа предусмотрена маска `MASK_LAST_WORD=0x0000FFFF`.

8-битный контейнер предоставляет `get_byte()`, `set_byte()`, `get_packed()`, `set_packed()`, преобразование к `uint8_t`, побитовые операторы, вывод и загрузку из вектора со смещением. Для одного полезного байта перестановка порядка байт не требуется.

## Пример

```cpp
#include "InOutData112.hpp"
#include "InOutData8.hpp"

InOutData112 payload;
payload.clear();
payload.set_word(0, 0x12345678u);
payload.set_word(3, 0x0000ABCDu);

InOutData8 control;
control.set_byte(0x05);
auto value = control.get_byte();
```

## Сборка и запуск

Нужны компилятор g++ с поддержкой C++17, GNU Make. Команды выполняются в корне соответствующей ветки:

```sh
make
make run
make rebuild-release
make run-release
```

По умолчанию собирается `bin/otu4_datatype_test_debug`, release-версия – `bin/otu4_datatype_test`. `make clean` удаляет результаты сборки. При смене конфигурации используйте пересборку: debug и release используют общие объектные файлы.
